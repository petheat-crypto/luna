# Луна Академия

Локальное учебное приложение без внешних npm-зависимостей. Требуется Node.js 20+.

## Запуск
Дважды нажмите `Запустить Луна Академию.bat`. Откроется `http://127.0.0.1:4173`. Сервер работает, пока открыто его окно.

Отдельные страницы с полной загрузкой документа: `/login`, `/dashboard`, `/catalog`, `/course/computer` (также `mouse`, `internet`, `email`, `safety`, `video`), `/notifications`, `/help`.

Демо-пользователи: `ivan / 1234`, `maria / 1234`, `test / test`.

## Вход через Google
Кнопка выполняет OAuth-вход Google с проверкой state, nonce и подписи ID-токена. Секрет уже помещён в локальный `.env` и исключён из git. Если его потребуется обновить, замените значение `GOOGLE_CLIENT_SECRET` в этом файле и перезапустите сервер. В Google Cloud Console должны быть разрешены redirect URI `http://127.0.0.1:4173/enter` и origin `http://127.0.0.1:4173`; если экран OAuth в режиме тестирования, добавьте свой аккаунт в список тестовых пользователей.

Сервер работает только пока запущен процесс Node.js. Данные прогресса хранятся в `data.json`; сессии действуют до 8 часов и сбрасываются после перезапуска. Сессионная cookie HttpOnly и SameSite=Lax; выбор cookie-согласия хранится год в браузере. Нет аналитических/рекламных скриптов и сторонних cookie. Google Fonts запрашиваются отдельно только для шрифта.

Пользователи и пароли являются тестовыми и заданы в `server.js`; для публикации в интернете необходимо подключить настоящую базу пользователей и безопасное хранение паролей.

Проверка: `node --test server.test.js`.

## Планировщик «Мои дела»
В той же папке: `Запустить Мои дела.bat` запускает отдельный планировщик на `http://127.0.0.1:4174`, не затрагивая учебный портал на порту 4173. Это самостоятельное приложение; наборы дел Нины, Бориса и тестового пользователя хранятся отдельно в `localStorage` браузера.

Сайт планировщика на GitHub Pages: `https://petheat-crypto.github.io/luna/` (источник — `main` / `docs`). Это статическая версия: дела и демо-вход хранятся только в браузере, Node-сервер на Pages не запускается; проверка Google-входа также клиентская и не защищает серверные данные. Для кнопки Google добавьте в Google Cloud Console разрешённый JavaScript origin `https://petheat-crypto.github.io`; OAuth-клиентный секрет на сайт не выкладывается.

Вход по логину и паролю теперь показан в локальном iframe (`planner-login.html`), а Google-вход остаётся отдельной кнопкой снаружи фрейма. Фрейм работает только с того же адреса планировщика; пароль не отправляется родительской странице — она получает только проверенный демо-профиль.

Проверка планировщика: `node --test planner.test.js`.

Вход Google использует тот же секрет из `.env`. В Google Cloud Console для этого OAuth-клиента нужно добавить ещё один разрешённый redirect URI: `http://127.0.0.1:4174/enter` (и, если настроены origins, `http://127.0.0.1:4174`). Старый адрес `4173/enter` оставить для портала курсов. Без этого Google отклонит вход с ошибкой `redirect_uri_mismatch`.
